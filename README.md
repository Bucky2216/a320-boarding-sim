## 这个页面在算什么

A320 典型单通道布局：30 排 × 3-3 共 180 座，全部从前舱门登机。
关键是通道只有一条，**谁在过道里放行李，后面的人就无法超越、只能等**，
等待时间累积起来就是不同登机顺序耗时差异的来源。

页面上可以：

- 选 6 种登机顺序（随机 / 前→后 / 后→前分 3 区 / 后→前严格按排 / 窗户优先 / Steffen 交错），播放动画看堵塞过程
- 实时调整「放行李耗时」「入座让路耗时」「舱门放行间隔」三个参数重跑
- 一键跑「全部顺序对比」：每种顺序多次运行取平均，出柱状图 + 明细表

默认参数下的典型结果（每种顺序 12 次取平均）：

| 登机顺序 | 平均总耗时 | 相对随机 |
|---|---|---|
| Steffen 交错（隔 3 排 + 左右交替） | 07:49 | 49% |
| 随机顺序 | 16:08 | 100% |
| 窗户优先（窗 → 中 → 通道） | 19:11 | 119% |
| 从后到前 · 分 3 区（区内随机） | 19:30 | 121% |
| 从后到前 · 严格按排（同排一起上） | 37:53 | 235% |
| 从前排到后排 | 48:16 | 299% |

三个反直觉的点：

1. **严格从后排按排分组反而比随机还慢** —— 同一排 6 个人连着上，只有一处放行李的位置，只能排队轮流放。
2. **前排先上最差** —— 后面每个人都要越过前面所有正在放行李的人，通道全程堵死。
3. **决定耗时的是"要不要越过正在放行李的人"** —— 所以让相邻两位乘客的座位隔开几排（Steffen）收益最大。

> 页面里的绝对时间是模型量，不是真实航班统计值。现实中单通道满客登机通常 15~30 分钟，
> 本模型把"排队纪律"理想化了，所以交错顺序显得特别快，实际收益会小一些。

## 本地怎么打开

双击 `index.html` 用 Chrome 打开即可，也可以用本地服务：

```bash
cd /Users/bunny/tools/a320-boarding-sim
python3 -m http.server 8000 --bind 127.0.0.1   # 然后访问 http://127.0.0.1:8000/
```

单文件、内联 CSS/JS、无外部依赖、无构建步骤，任何静态托管都能直接跑。

## 改了之后怎么更新线上

本机当前网络环境下 **git 传输通道（`github.com/<仓库>.git`）被阻断**，
但 `api.github.com` 正常，所以用 Contents API 提交（与刷题站同一套做法）：

```bash
cd /Users/bunny/tools/a320-boarding-sim
python3 tools/upload_via_api.py            # 上传全部文件
python3 tools/upload_via_api.py index.html # 只上传某个文件
```

脚本会先查远程文件的 sha 再提交，因此可以重复运行做覆盖更新；推送后约 30 秒 Pages 生效。
前提是 `gh` 保持登录：`gh auth status` 能看到 ✓ Logged in 即可。
