# 客机登机顺序模拟（多机型）

## 在线地址

GitHub Pages 静态托管，手机、电脑打开即用；纯前端单文件，打开后不需要联网。
仓库地址：https://github.com/Bucky2216/a320-boarding-sim

## 这个页面在算什么

模拟一飞机的人从舱门走到自己座位、放行李、坐下的全过程，
关键机制是：**通道里谁在放行李，同一条通道后面的人就无法超越，只能等**，
等待时间累积起来就是不同方案的耗时差异。

机型差异体现在三件事上：

1. 每排怎么分段：3-3 / 2-2 / 3-3-3 / 2-4-2 / 3-4-3
2. 有几条通道：窄体 1 条、宽体 2 条，两条通道互不干扰
3. 开几个门：只开前门，还是前门 + 后门各自排一条队

内置 10 种机型：A319、A320、A321、737-800、E190、A320（前后门）、787-9、A350-900、A330-300、777-300ER。

页面上可以：

- 选机型 + 选登机顺序，播放动画看堵塞过程（橙色＝正在放行李，红色＝被堵住原地等）
- 实时调整「放行李耗时 / 入座让路耗时 / 每个舱门放行间隔」重跑
- 「对比 6 种登机顺序」：固定机型，每种顺序多次运行取平均
- 「对比 10 种机型」：固定顺序，按**每人耗时**比较不同机型的登机效率

## 典型结果（默认参数，各 12 次取平均）

同一架 A320（180 座，单通道单门），只换登机顺序：

| 登机顺序 | 平均总耗时 | 相对随机 |
|---|---|---|
| 窗户优先（窗 → 中 → 通道） | 05:43 | 36% |
| Steffen 交错（隔 3 排） | 07:49 | 50% |
| 随机顺序 | 15:47 | 100% |
| 从后到前 · 分 3 区（区内随机） | 18:23 | 116% |
| 从后到前 · 严格按排（同排一起上） | 36:41 | 232% |
| 从前排到后排 | 45:04 | 285% |

同样是随机顺序，只换机型（按每人耗时排序）：

| 机型 | 布局 | 座位 | 每人耗时 | 平均总耗时 |
|---|---|---|---|---|
| 777-300ER | 双通道 3-4-3 · 双门 | 440 | 1.5 秒 | 10:43 |
| A350-900 | 双通道 3-3-3 · 双门 | 387 | 1.5 秒 | 09:49 |
| A330-300 | 双通道 2-4-2 · 双门 | 352 | 1.6 秒 | 09:30 |
| 787-9 | 双通道 3-3-3 · 单门 | 378 | 2.5 秒 | 15:48 |
| A320（前后门） | 单通道 3-3 · 双门 | 180 | 3.2 秒 | 09:28 |
| A321 / 737-800 / A320 / A319 | 单通道 3-3 · 单门 | 216 / 192 / 180 / 150 | 4.7 ~ 5.8 秒 | 14:35 ~ 16:51 |
| E190 | 单通道 2-2 · 单门 | 100 | 5.0 秒 | 08:17 |

几个反直觉的点：

1. **严格从后排按排分组反而比随机还慢** —— 同一排的人连着上，只有一处放行李的位置，只能排队轮流放。
2. **前排先上最差** —— 后面每个人都要越过前面所有正在放行李的人。
3. **"开两个门"不必然更快** —— 登机顺序是按机舱位置叫的（比如从后排往前排），开后门时后门那一队变成"越走越远"，每个人都要越过前一位正在放行李的人。787-9 只有前门（2.5 秒/人）就比同尺寸的 A350-900 双门（1.5 秒/人）慢 60%。
4. **宽体机每人耗时最低** —— 两条通道 + 两个门可以真正并行。

> 页面里的绝对时间是模型量，不是真实航班统计值。现实中窄体机满客登机通常 15~30 分钟；
> 本模型假设每位乘客都按排队次序老实往前走，所以交错顺序显得特别快，实际收益会小一些。

## 改了之后怎么更新线上

本机当前网络环境下 **git 传输通道（`github.com/<仓库>.git`）被阻断**，
但 `api.github.com` 正常，所以用 Contents API 提交（与刷题站同一套做法）：

```bash
cd /Users/bunny/tools/a320-boarding-sim
python3 tools/upload_via_api.py            # 上传全部文件
python3 tools/upload_via_api.py index.html # 只上传某个文件
```

脚本会先查远程文件的 sha 再提交，因此可以重复运行做覆盖更新；推送后约 30 秒 Pages 生效。
前提是 `gh` 保持登录：`gh auth status` 能看到 ✓ Logged in 即可。

## 文件说明

```
index.html              ← 应用本体（仿真引擎 + 动画 + 图表，全部内联）
tools/upload_via_api.py ← 备用上传通道（git 被阻断时使用）
```

## 模型参数（页面右侧可调）

| 参数 | 默认 | 含义 |
|---|---|---|
| 放行李平均耗时 | 9 秒 | 对数正态分布，少数人很慢；0 秒可看"没有行李"的情况 |
| 入座让人让路耗时 | 8 秒 | 入座路径上每位已就座乘客需要起身让路的额外耗时 |
| 每个舱门放行间隔 | 1.5 秒/人 | 舱门瓶颈，开两个门相当于把这个下限并行化 |
